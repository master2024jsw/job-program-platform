# 잡도리 AI v2 — 인수·회귀 테스트 명세

작성일: 2026-10-15 · **이 문서는 테스트 계획입니다. 아래 51개 테스트는 모두 NOT_RUN입니다.**

> **주석:** PASS는 실제로 실행하고 기대 결과를 확인한 경우에만 표시합니다. 코드가 있어 보이거나, 화면에 버튼이 있다는 이유로 PASS로 바꾸지 않습니다. 이 문서 작성 중에는 애플리케이션 실행·Windows 설치·외부 메일·실제 AI 분석을 검증하지 않았습니다.

## 1. 공통 준비

테스트는 임시 DB와 합성자료를 사용합니다. 실제 .env, 실제 주민등록번호·급여·계좌자료, 운영 메일함을 기본 테스트에 넣지 않습니다. SMTP/IMAP/추출 어댑터는 모의 응답을 사용합니다.

| 준비물 | 용도 | 쉬운 설명 |
| --- | --- | --- |
| 기관 A/B, 사업 A1/A2/B1 | 권한 경계 검증 | 실제 출시를 다기관 SaaS로 확장한다는 뜻은 아닙니다. 접근 누출 검사에만 씁니다. |
| 관리자, 사업 A1 담당자, 승인권자, 접수배정자 | 역할·기능 권한 검증 | ADMIN이라는 이름만으로 자동 승인권을 주지 않습니다. |
| 합성 기업·근로자와 사업별 참여기록 | 사람과 사업 이력 분리 | 같은 사람이 다른 조건으로 참여해도 자료가 유지되어야 합니다. |
| 정상·누락·불일치·여러 사람 혼합 PDF | 문서 파이프라인 검증 | 파일 하나가 서류 한 건이라고 가정하지 않습니다. |
| 모의 시계·정해진 기준일 | 날짜 규칙 검증 | 테스트 실행일이 바뀌어도 같은 결과가 나와야 합니다. |
| 작은 기존 스키마 복제 DB | 마이그레이션·복구 검증 | 실제 민감자료 대신 스키마와 관계를 재현합니다. |
| 오류를 주입하는 모의 어댑터 | 실패·재시작·부분 성공 검증 | 일부러 에러를 내서 자료가 깨지지 않는지 확인합니다. |

출처가 없는 공식 지급기준은 테스트에 확정값으로 넣지 않습니다. `examples/`의 정책은 합성 예시이며 실제 사업에서 사용할 수 없습니다.
