## 1. 고용보험이력·교육대장만 workerId가 붙은 이유

### 근본 원인: `extractBirthDate()`의 입력값 차이

`groupWorkerDocuments`의 핵심 분기:

```typescript
const birthDate = extractBirthDate(data);
if (!birthDate) return; // → workerId 미부여
```

각 서류의 현재 `extractedData`에 생년월일 관련 필드가 있는지가 전부를 결정한다.

| 서류 | Gemini 추출 필드 | `extractBirthDate` | 묶임 |
|------|-----------------|-------------------|------|
| 고용보험이력 | `birthDate` 직접 (구 스키마부터 존재) | ✅ 날짜 반환 | O |
| 교육대장 | `birthDate` 직접 (구 스키마부터 존재) | ✅ 날짜 반환 | O |
| 신청서 | `residentNumber` 있으나, 이미 `workerId`가 붙어있고 Worker 레코드 생존 → `if (workerId && exists) return` 조기 반환 | (실행 안 됨) | △ |
| 주민등록초본 | `residentNumber` 있어야 하나 이전 500 오류로 분석 실패 → `extractedData` null/빈값 | ❌ null | X |
| 개인정보동의서 | 구 스키마에 `residentNumber` 없었음. 이번 변경으로 추가했으나 **재분석 전 `extractedData`엔 없음** | ❌ null | X |
| 근로계약서 | 마찬가지. `residentNumber`/`birthDate` 이번에 추가했으나 재분석 전 `extractedData`엔 없음 | ❌ null | X |
| 적격확인서 | 스키마 자체에 주민번호·생년월일 없음 (체크박스만) | ❌ 구조적 한계 | X |

### 백필(backfill)도 같은 이유로 차단됨

고용보험이력이 Worker를 생성한 뒤 형제 서류를 찾는 로직:

```typescript
// documents.service.ts — groupWorkerDocuments()
if (extractBirthDate(d) === birthDate) toBackfill.push(c);
```

개인정보동의서·근로계약서는 `extractedData`에 주민번호가 없어 `extractBirthDate`가 null을 반환하므로 백필 대상에서 제외된다.

### 서류별 조치 방법

| 서류 | 필요한 조치 |
|------|------------|
| 개인정보동의서 | **재분석** — 이번 스키마 변경으로 Gemini가 `residentNumber` 추출 가능 |
| 근로계약서 | **재분석** — `residentNumber` / `birthDate` 추출 가능 |
| 주민등록초본 | **재분석** — 이전 500 오류 재시도, `residentNumber` 추출 후 그룹핑 |
| 신청서 | 재분석 시 `recalcWorkerName`으로 이름만 재계산됨 (이미 Worker에 연결) |
| 적격확인서 | 스키마에 주민번호 없음. 해결하려면 gemini.service.ts `ELIGIBILITY_CONFIRM` 스키마에 `residentNumber` 추가 필요 (실제 서류에 표기 여부 먼저 확인) |
