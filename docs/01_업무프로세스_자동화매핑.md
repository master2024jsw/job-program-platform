# 01. 업무프로세스 자동화매핑

> Claude Code 참고용 기준 문서. 논문(ver.12) Ⅲ장 4.1~4.2절과 실무 매핑표(업무프로세스_자동화매핑)를 합친 것.
> 기능을 새로 만들거나 우선순위를 판단할 때 **이 문서의 "논문 1차 범위"를 최우선**으로 한다.

## 0. 두 가지 "9단계"가 있다 — 혼동 주의

| 구분 | 기준 | 쓰이는 곳 |
|---|---|---|
| **A. 사업 업무흐름 9단계** | 현장실습훈련 지원사업 운영안내(한국노인인력개발원, 2026) | 논문 Ⅲ장 <표 3-5>, 검증엔진 설계 |
| **B. 수행기관 행정업무 9단계** | 실무자 행정업무 전체(사업계획서~민원응대) | 앱 메뉴 구성, `guide-content.ts`의 FLOW_STEPS |

A는 "서류 검증"의 흐름이고, B는 "기관 행정 전체"의 흐름이다. 논문의 핵심 기여는 **A의 ②⑥⑦(적격 확인·서류검증)** 구간이다.

## 1. [A] 사업 업무흐름 9단계 — 논문 기준 (핵심)

1차 적용 사업: **현장실습훈련 지원사업(시니어인턴십)**, 코드상 `typeCode = SENIOR`
2차 확대 예정: 청년일자리도약장려금 (`YOUTH`)

| 단계 | 기존 방식 | 설계 방식 | 유형 |
|---|---|---|---|
| ① 참여기업 신청 | 메일·방문 접수 후 수신 확인·저장 | IMAP 메일·첨부 자동수집, 압축 해제, PDF 표준화 | RPA |
| ② 기업 적격 확인 | 서류 육안 확인, 지침 요건 대조 | AI 판독 항목 추출 → 교차검증 규칙으로 요건 대조 | IPA |
| ③ 협약 체결 | 협약서 작성·날인 | 범위 제외 | - |
| ④ 근로자 구인 | 기업 자체 채용 | 범위 제외 | - |
| ⑤ 참여자 신청 | 메일·방문 접수 | ①과 동일한 자동수집·표준화 | RPA |
| ⑥ 참여자 적격 확인 | 연령·자격 수기 계산, 서류 대조 | AI 판독 + 도메인 검증으로 자격요건 자동 판정 | IPA |
| ⑦ 지원금 신청 서류검증 | 임금명세서·4대보험 명부 육안 대조, 근속·금액 계산 | 교차검증·자동계산·예외처리 규칙 순차 적용 | IPA |
| ⑧ 지원금 지급 | 검증 결과 최종 확인 후 승인·이체 | 원본 서류와 AI 결과를 대조 화면으로 제시, **실무자 최종 승인** | RDA(인간개입) |
| ⑨ 사후관리 | 중복참여·이중취득 수기 점검 | 판정 이력 기반 상시 점검, 위험탐지 규칙 알림 | RPA·IPA |

### 1.1 도메인 검증엔진 — 규칙 4유형

규칙은 **코드에 고정하지 않고 데이터로 분리**한다(REQ3). 지침 개정 시 코드 수정 없이 규칙만 갱신한다.

| 유형 | 코드명 | 의미 | 예시 |
|---|---|---|---|
| 교차검증 | `crossCheck` | 복수 서류의 값 일치 확인 | 예금주=대표자, 4대보험 취득일 일치 |
| 자동계산 | `calcRule` | 기준일 기준 계산 | 만연령 산출, 근속월수→지원금 회차·금액 |
| 예외처리 | `exceptionRule` | 지침에 없는 실무 예외 | 법인전환 시 4대보험 승계 판정, 계좌 압류 시 제3자 지급 |
| 위험탐지 | `riskFlag` | 서류상 하자는 없으나 실질 위험 | 사업장 소재지가 공유오피스 → 현장확인 대상 |

규칙 위반이나 위험 신호가 있는 건은 **자동 승인하지 않고** 실무자 검토로 넘긴다.

### 1.2 단계별 검증 대상 (논문 <표 3-6>)

| 단계 | 확인 사항 | 서류 |
|---|---|---|
| 기업 적격 확인 | 4대보험 가입 사업장 여부, 근로자보호 규정 준수, 신규설립기업 참여인원·협약기관 수 상한 | 참여기업 신청서, 사업계획서(세대통합형) |
| 참여자 적격 확인 | 연령요건(60세 이상, 1966년생 이전 출생), 기존 취업 여부(중복참여 배제), 교육 이수 | 참여신청서, 개인정보 동의서, 건강보험자격득실확인서 |
| 지원금 검증(일반형) | 근무 3개월 경과, 출근 여부, 근로계약 조건 일치 | 임금명세서, 근로계약서, 출근부 |
| 지원금 검증(세대통합형) | 6개월 이상 고용, 누적 급여총액 ≥ 보조금(300만 원) | 근로계약서, 청년멘토 활동보고서, 임금명세서 |
| 지원금 검증(장기취업유지형) | 공백 없는 4대보험 갱신, 계약기간에 신청일 포함 | 근로계약서, 4대보험 가입자 명부, 서약서 |
| 지원금 검증(예외) | 법인전환 동일인 승계, 계좌 압류 시 제3자 지급 요건 | 법인전환 증빙, 위임장 |
| 사후관리 | 타 재정지원사업 중복참여, 4대보험 이중가입, 재참여 제한 | 노인일자리정보시스템, 4대보험 가입내역 |

### 1.3 실무자 검토·보정 인터페이스 설계 원칙 (REQ4)

1. **선별 제시**: 낮은 확신도 또는 규칙 위반·위험 신호 항목만 강조 표시
2. **근거 제시**: 원본 서류와 추출값을 나란히 배치, 어떤 규칙이 왜 그렇게 판정했는지 표시
3. **이력 축적**: 승인·수정 이력을 판정 이력 DB에 저장, 실무자 수정 이력은 규칙 보완에 활용

## 2. [B] 수행기관 행정업무 9단계 — 실무 매핑표

## 3. 논문 1차 개발 범위 (최우선)

| 범위 | 요구사항 | [A] 단계 | [B] 단계 |
|---|---|---|---|
| 서류 수집·자동 접수 (메일 수집, PDF 표준화) | REQ1 | ①⑤ | 4·5·6단계 수집부 |
| AI 문서분석 + 도메인 검증 (JSON 추출, 사업별 자격요건 1차 검증) | REQ1·2·3 | ②⑥⑦ | 4·5·6단계 검토부 |
| 실무자 검토·보정 인터페이스 | REQ4 | ⑧ | 7단계 |
| 로컬 온프레미스 아키텍처 | REQ5 | 전체 | 전체 |

**1차 범위 밖**(논문 Ⅵ장 향후 과제): 신사업 공고 수집, 참여기업 발굴, 운영기관 평가, 민원응대.
→ 이미 구현된 신사업 알리미·기업 DB·메일은 유지하되, **새 개발 시간은 1차 범위에 우선 배정**한다.

## 4. 요구사항 요약 (논문 <표 3-3>)

| REQ | 내용 |
|---|---|
| REQ1 | 비정형 서류 자동 수집·구조화 |
| REQ2 | 서류 간 교차 검증 |
| REQ3 | 예외 상황의 규칙화, 지침 개정을 코드 수정 없이 반영 |
| REQ4 | 실무자 최종 검토 보장 (AI 판정은 최종 결정이 아님) |
| REQ5 | 기관 내부 완결형 데이터 처리 |

## 5. 자동화하지 않는 영역 (사람 유지)

- 정부시스템(e나라도움, 전산등록) 입력·업로드
- 고용보험 자격 최종 크로스체크 (확인서 위조·취업상태 누락 사례)
- 지원금 지급 최종 승인
- 상위기관(개발원) 질의
