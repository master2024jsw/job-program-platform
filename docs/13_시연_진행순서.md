>
> **산정 공식이 두 곳에서 다릅니다.** 오늘 확인된 사실입니다.

>
> **질문이 나오면**: "산정 화면은 일할계산만 하고 월상한 적용이 빠져 있습니다.

### B-3. 근로자 서류 올리고 분석 — **근로자를 먼저 등록하지 마세요**

> ### ⚠️ 리허설에서 확인한 것 — 근로자가 두 명이 됩니다
>
> **참여자 서류를 분석하면 시스템이 근로자를 자동으로 만듭니다.**
> 성명·생년월일은 참여자 신청서에서, 급여·입사일은 근로계약서에서 가져옵니다.
>
> 그래서 `+ 근로자 추가` 로 **먼저 등록해 두면 박영수가 두 명**이 됩니다.
> (리허설에서 실제로 그렇게 됐고, 중복된 쪽을 지웠습니다.)
>
> **서류를 먼저 올리고 분석하세요.** 근로자 등록은 시스템이 합니다.

**`문서함`** — B-2와 같은 방법으로 `2_참여자적격` **7개**를 올리고 `선택 분석 (7)`

분석이 끝나면 `연결된 기업/근로자` 칸에 **한빛물류(주) / 박영수** 가 나옵니다
(리허설에서 7건 전부 자동 연결됐습니다).

연결이 안 된 서류가 있으면: 그 행의 `검토` → **관련 근로자** 에서 `박영수` 선택 → `검토 완료 저장`

그다음 `근로자 관리` → 박영수 행 → `신청 검증`

> 자동으로 만들어진 근로자에는 **주소·이메일이 비어 있습니다.** 필요하면
> `근로자 관리` 에서 그 행을 열어 채우면 됩니다. 검증에는 영향이 없습니다.

### B-4. 지원금

**`문서함`** — `3_지원금신청` 6개 올리고 분석
**`지원금 안내`** → 상단 탭 `서류 검증` → 기업 선택

> `산정 관리` 탭은 누르지 마세요 — 위 A-4의 ⚠️ 참고 (공식이 달라 금액이 어긋납니다).

## 질문이 나오면

| 질문 | 답할 것 |
|---|---|
| 예외규칙은 몇 건? | 4건 (crossCheck 11 / calcRule 12 / riskFlag 5 / exceptionRule 4 = 32) |
| 왜 예외규칙이 적은가? | 지침에 없고 담당자 경험에만 있어서 **받을 구조를 먼저** 만들었다. 「예외 후보」 화면이 반복 승인을 찾아 주고, 사람이 판단해 등록한다 |
| AI가 틀리면? | 예외규칙도 자동 통과가 없다. 전부 `확인필요`로 사람에게 넘긴다 (ADR-07) |
| 실무자가 규칙을 직접 넣을 수 있나? | **아직 없다. 향후 과제.** 지금은 담당자가 적고 JSON 원장에 등록한다 |
| 실제 자료로 썼나? | 화면의 것은 합성 자료다. 실제 자료로도 운영했다 (실제 자료는 개인정보라 시연에 띄우지 않는다) |
| 개인정보가 외부 AI로 나가나? | **글자가 추출되는 PDF는 본문의 주민번호 뒤 6자리를 가려서 보낸다.** 생년월일·성별 자리만 남기는데 만연령 확인에 필요해서다. 마스킹 전후 추출 결과가 같은 것을 실제 서류로 확인했다. **다만 스캔 이미지 PDF는 이미지에 찍힌 번호를 가릴 수 없어 원본이 나간다** — 가리려면 PDF를 렌더링해 영역을 덧칠(redaction)해야 하고 구현하지 않았다. 그 경로는 ZDR(미학습·즉시삭제) 정책에 의존한다. 논문 §8 한계 7번에 그대로 적었다 |
| DB에는 주민번호가 저장되나? | 추출 결과는 저장 전에 마스킹한다(`maskDeep`). 담당자 승인 사유 칸은 앞자리까지 전부 가린다 — 여러 건을 모아 보는 화면이라서다 |
| 사용자 평가에 이 기능이 포함됐나? | **아니다.** 평가는 11/1~9, 예외처리 구조는 11/13~14 구현이다 |

## 잘 안 될 때

| 증상 | 할 일 |
|---|---|
| 화면이 안 열린다 | 터미널에 `npm run restart:web` |
| 로그인했는데 메뉴가 비었다 | 사업 선택을 안 했다. 로그아웃 후 다시 로그인하며 사업 선택 |
| 검증 화면이 비었다 | 기업 선택 드롭다운을 안 눌렀다 |
| 분석이 `실패` 로 뜬다 | AI 호출 실패. 그 행의 `분석` 다시 클릭. 계속 실패하면 **그 서류는 건너뛰고 설명으로 넘어가세요** |
| 분석이 오래 걸린다 | 정상이다 (한 건 10~30초). 기다리는 동안 다른 화면을 설명하세요 |
