# 예외사항·암묵지 수집 양식 (심사③ 대응)

작성 시작: 2026-11-04 · 작성자: 정세원 · 상태: **수집 중** (구조 2026-11-13 구현 · 예외규칙 **4건 등록** 2026-11-14)

---

## 왜 이걸 쓰나

예비발표 심사 지적 ③번이 **"예외사항·암묵지를 별도 섹션으로 분리하라"**였고, 지금 🔴 미구현입니다.

```
현재 규칙 28개 =  crossCheck 11  +  calcRule 12  +  riskFlag 5  +  exceptionRule 0
                                                                              ↑ 여기가 비어 있음
```

**왜 비어 있나:** 예외규칙은 지침서에 없습니다. **실무자 머릿속에만 있습니다.**
코드로 만들 수 없는 게 아니라, **내용을 아는 사람이 적어줘야** 만들 수 있습니다.

그래서 이 문서는 **선생님이 채우는 문서**입니다. 제가 대신 쓸 수 없습니다.

### 채우면 두 군데에 쓰입니다

1. **논문** — 규칙 출처·버전관리 표, 심사③ 대응 근거
2. **코드** — `exceptionRule` 원장(JSON)으로 변환 → 실제 동작하는 규칙

### E-02. 사업 기간 중 법인전환으로 사업자등록번호가 달라진 경우

> **담당자 확인 2026-11-14: 실제로 겪은 상황이고, 처리 절차까지 확인됨.**
> 탐지 조건과 확인 서류 모두 원장에 등록했습니다 (`R-101-E1` version 2).

- **언제 생기나**
  사업 기간 중 개인사업자가 법인으로 전환해 사업자등록번호가 달라진 경우.
  R-101(사업자등록번호 3자 일치)에서 불일치로 걸린다. 실질은 같은 사업장이다.

- **왜 지침만으로는 안 되나**
  지침은 "동일 사업장"을 전제하는데, 법인전환이면 번호가 달라져 서류 대조로는 다른 사업장으로 보인다.

- **자동으로 잡아내는 조건** *(등록 완료)*
  사업자등록번호 불일치 + **대표자 동일** + **상호 유사**(㈜·(주)·주식회사 등 법인격 표기 제거 후 비교)
  → "법인전환 의심"으로 `확인필요` 표시 + 확인 절차 안내

- **실무에서는 어떻게 처리하나** *(2026-11-14 담당자 확인)*
  아래 세 서류를 받아 **고용승계를 확인**한다. 확인되면 승계로 보고 승인한다.
  서류가 갖춰지지 않으면 승인하지 않는다 — 사업자번호만 다른 별개 사업장일 수 있다.

- **추가로 받는 서류** — 3종 모두
  1. **법인양도양수 계약서**
  2. **고용승계확인서**
  3. **개인사업자에서 법인으로 전환된 것이 나타나는 고용보험 가입이력내역서**

- **출처**
  [x] 실무 경험 — 2026-11-14 담당자 확인 (빈도·시기 ❓)
  (❓ 상급기관 회신으로 확인한 적이 있으면 그 내용이 가장 강한 근거가 됩니다)

### E-03. 기업 계좌가 압류되어 사업체 명의 계좌로 지급할 수 없는 경우

> **담당자 확인 2026-11-14: 실제로 겪은 상황이고, 처리 절차까지 확인됨.**
> 지급 방법이 **두 가지**로 갈립니다 (`R-308c-E1` version 2).

- **언제 생기나**
  기업 계좌가 압류되어 지원금을 받을 수 없는 경우. 다른 명의 계좌를 제출하게 되고,
  R-308c(통장 예금주 = 기업 상호)에서 불일치로 걸린다.

- **왜 지침만으로는 안 되나**
  지침은 "사업체 명의 계좌"를 요구하는데, 압류되면 그 계좌로는 입금이 안 된다.

- **자동으로 잡아내는 조건** *(등록 완료)*
  통장 예금주 ≠ 기업 상호 → "압류로 인한 제3자 계좌 가능성"으로 `확인필요` 표시 + 확인 절차 안내
  (압류 사실 자체는 서류에 없으므로 자동 판정은 불가)

- **실무에서는 어떻게 처리하나** *(2026-11-14 담당자 확인)*
  계좌가 압류되었으면 **현금지급** 또는 **제3자 지급** 두 가지가 있다.

  | 지급 방법 | 받는 서류 |
  |---|---|
  | **현금지급** | **현금수령확인서** |
  | **제3자 지급** | **제3자의 통장사본** + **관계를 증명할 수 있는 서류**(가족관계증명서 등) |

  어느 쪽이든 서류가 갖춰져야 승인한다.
  압류가 아니라 단순 오기·오제출이면 사업체 명의 통장사본을 다시 받는다.

- **판정**
  [x] 추가 서류를 받아 확인 후 결정

- **출처**
  [x] 실무 경험 — 2026-11-14 담당자 확인 (빈도·시기 ❓)

- **등록 상태**
  **등록 완료 (2026-11-14, version 2)** — `SENIOR-subsidy.json` → `companyExceptionRules` → `R-308c-E1`
  탐지 조건 + 두 가지 지급 방법별 서류 안내까지 포함

- **언제 생기나**
  사업자등록증의 업태·종목이 사무실에서 하는 업종(컨설팅·IT·사무지원 등)이고,
  사업장 소재지가 공유오피스·비즈니스센터로 의심되는 주소일 때.

- **왜 지침만으로는 안 되나**
  **지침에 사업장의 장소에 관한 규정이 없다.** 그래서 공식 요건으로는 아무것도 걸리지 않는다.
  서류는 전부 멀쩡하지만, 실제로 그 장소에서 업무를 하는지는 서류로 확인할 수 없다.

- **실무에서는 어떻게 처리하나** *(2026-11-14 담당자 확인)*
  **현장확인을 나가 두 가지를 보고 온다.**
  1. 그 장소에서 **실제로 근무를 하고 있는지**
  2. **어떤 업무를 하고 있는지**

  보고 온 내용을 승인 사유에 남긴다.
  (처음에 제가 적어 둔 「상시 근무 인원·책상·장비·간판·계약 형태」는 추측이었고,
  실제 확인 항목은 위 두 가지입니다 — 규칙 안내문도 이 두 가지로 바꿨습니다.)

  (❓ 근무가 확인되지 않을 때 반려인지 보류인지는 아직 안 적었습니다 —
  안내문은 "확인 결과를 사유에 남기고 담당자가 결정"까지만 말합니다)

## 적은 내용이 규칙이 되는 과정 (참고)

채워 주시면 제가 이렇게 바꿉니다. **선생님이 JSON을 쓰실 필요는 없습니다.**

**선생님이 적는 것**
> 법인전환이면 사업자번호가 달라서 3자 대조에 걸리는데, 대표자가 같고 상호가 비슷하면
> 법인전환 증빙을 받아서 통과시킨다.

**제가 만드는 것**
```json
{
  "id": "R-110",
  "type": "exceptionRule",
  "label": "법인전환 시 사업자번호 불일치 예외",
  "appliesWhen": { "failedRule": "R-101" },
  "conditions": [
    { "field": "representativeName", "match": "equal" },
    { "field": "companyName", "match": "similar" }
  ],
  "requiresDocument": "CORPORATE_CONVERSION_PROOF",
  "onMatch": "NEEDS_REVIEW",
  "source": {
    "kind": "실무경험",
    "note": "담당자 확인 2026-11",
    "registeredBy": "정세원",
    "registeredAt": "2026-11-__"
  }
}
```

`source` 블록이 심사③이 요구한 **"출처·등록자·등록일 기록"**에 해당합니다.

---

## 몇 건이면 충분한가

**3~5건이면 논문에 쓸 수 있습니다.** 많을 필요 없습니다.

- 1~2건: 예시 수준. "이런 게 있다" 정도
- **3~5건: 유형이 보임.** 분류해서 표로 만들 수 있음 ← 목표
- 6건 이상: 좋지만, 질이 더 중요합니다

**출처가 명확한 1건**이 **출처가 흐릿한 5건**보다 낫습니다.
"어디선가 들었는데"는 논문에 쓰기 어렵습니다. 확실한 것만 적어주세요.

## 원장 등록 절차

수집 양식에 적은 내용이 실제 규칙이 되기까지의 단계입니다. **사람이 검토하는 단계를 건너뛰지 않습니다.**

```
① 수집   이 문서에 사례를 적는다 (실무자)
② 검토   출처가 분명한가, 반복되는 유형인가 (담당자)
③ 등록   exceptionRules 에 추가 — source, version: 1 을 함께 적는다
④ 수정   내용이 바뀌면 version 을 올린다. 이전 내용은 git 이력으로 보존
```

등록 위치

| 대상 | 파일 | 배열 |
|---|---|---|
| 기업 신청 | `apps/server/resources/validation-rules/SENIOR-company.json` | `exceptionRules` |
| 근로자 신청 | `apps/server/resources/validation-rules/SENIOR-worker.json` | `exceptionRules` |
| 지원금 신청 | `apps/server/resources/validation-rules/SENIOR-subsidy.json` | `companyExceptionRules` / `workerExceptionRules` |

`source` 블록이 심사③이 요구한 **출처·등록자·등록일** 기록입니다. 없으면 등록하지 않습니다.

> 원장에 잘못 적어도 전체 판정이 깨지지 않습니다. `appliesWhen.failedRule` 이 같은 원장에 없거나
> `type` 이 `exceptionRule` 이 아니면, 그 규칙만 경고 로그와 함께 제외됩니다.

## 「예외 후보」 화면 — 기억에만 의존하지 않기

**평가 대응 탭 맨 위**에 예외 후보 표가 있습니다.
규칙에 걸렸는데 담당자가 그대로 승인한 건을 모아, 승인 횟수가 많은 순으로 보여 줍니다.

| 보이는 것 | 뜻 |
|---|---|
| 승인 횟수 | 걸린 채로 승인된 횟수. 많을수록 유형일 가능성이 큽니다 |
| 대상 수 | 서로 다른 기업·근로자 수. 1이면 일회성, 여러 건이면 반복되는 상황 |
| 승인 사유 | 승인할 때 적어 둔 근거 (최근 5건). 주민번호는 저장 전에 가려집니다 |

승인할 때 **걸린 규칙이 있으면 "승인 사유" 칸이 뜹니다.** 적어 두면 나중에 여기 모입니다.
깨끗한 건에는 뜨지 않으므로 평소 승인 동선은 그대로입니다.

**이 화면이 규칙을 자동으로 만들지는 않습니다.** 보고 판단해서 위 수집 양식에 옮겨 적는 것은 사람의 몫입니다
(ADR-07: AI는 추출, 규칙엔진은 대조, 사람은 결정).
